# intro-builder（写作08｜引言与相关工作写作）

引言最常见的失败不是写得不好，而是**把没验证过的东西写成缺口**（"此前无人研究"）。所以本 Skill 只从素材里取句子填槽，取不到就留空。

## 用法

```bash
python3 src/run_case.py --case input/case.json --out work
```

输入可以是 `.tex` / `.md` 草稿，也可以是 PDF（会同时抽取参考文献用于相关工作分组）。

## 三段结构

| 部分 | 线索 | 产出 |
|---|---|---|
| 1. 背景（已知） | `has become / widely used / 近年来 / 随着` | 带原文引句的槽位 |
| 2. 研究缺口（未知） | `however / remains unclear / limited / 不足 / 尚未` | 带原文引句的槽位 |
| 3. 本文贡献（新增） | `we propose / this paper / 我们提出` | 带原文引句的槽位 |
| 4. 相关工作分组 | 参考文献标题关键词聚类 | 主题 + 计数 + 示例 |

## 输出字段

| 字段 | 含义 |
|---|---|
| `skeleton[]` | 各部分的槽位与写作建议 |
| `missing_evidence` | 没有任何支撑句的要素，必须补材料或标注待补 |
| `related_work_themes[]` | 主题、出现次数、代表文献 |
| `text` | 把引句按部分拼成的草稿骨架 |

## 使用顺序

1. 先看 `missing_evidence`：缺 `gap` 就说明素材里没有能支撑缺口的句子，此时要么补调研，要么把该段标为待补，不要硬写。
2. 用 `skeleton` 的引句作骨架，扩写成段落。
3. 相关工作按 `related_work_themes` 分组评述，每组结尾写与本文的差异。

## 限制

- **不生成最终段落文本**：引句是素材，不是成稿；衔接与论证由 Agent 完成。
- 线索词是规则匹配，否定句（"not limited to"）可能被误判为缺口。
- 相关工作聚类基于参考文献标题词频，短标题或中文标题聚类效果差。
- 不做引文相关性判断，"主题分组"只是词面相近。

## 最小示例

```bash
python3 src/run_case.py --case demo/case.json --out work
```

输出会显示三段各有几个槽位、缺哪些要素、相关工作分成几个主题。
