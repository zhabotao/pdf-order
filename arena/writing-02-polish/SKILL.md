# prose-polish（写作02｜学术语言润色）

润色最大的风险是**悄悄改变含义**。所以本 Skill 把改动分成两档：能证明无害的自动改，其余只报告。

## 用法

```bash
python3 src/run_case.py --case input/case.json --out work
```

输入优先取 `.tex` / `.md` / `.txt`（可编辑源）；只有 PDF 时会退化到抽取文本，并在 `uncertainty` 里说明版式信息已丢失。

## 自动修的三类（不可能改变语义）

| 规则 | 作用 |
|---|---|
| `cjk_latin_spacing` | 中英文之间补空格 |
| `collapse_double_space` | 合并连续空格 |
| `strip_trailing_space` | 去行尾空白 |
| `normalize_cite_keys` | `\cite{a, b}` → `\cite{a,b}` |

## 只报不改的三类

- **超长句**（> 45 词）：给出行号与拆分建议，不替你拆——拆错会改变逻辑关系。
- **被动语态过密**：方法段可以保留被动，结论段建议改主动。
- **时态漂移**：统计现在时/过去时分布，`dominant` 只作参考。

## 输出字段

| 字段 | 含义 |
|---|---|
| `text` | 已应用安全修正后的全文 |
| `issues[]` | 逐条问题与建议 |
| `fixes_applied[]` | 实际执行的规则 |
| `stats` | 问题数、自动修正数、长句数、被动数、时态分布 |
| `repeated_terms[]` | 高频词，用来判断术语是否需要统一 |

## 限制

- **不做语义级改写**：同义替换、句式重组、逻辑衔接需 Agent 完成并复核。
- 长句判定用词数阈值，中文文本按词数不可靠，会偏少报。
- PDF 输入时无法识别原稿换行与缩进，格式类误报会增加。
- 只针对中英文；其他语言规则未覆盖。

## 最小示例

```bash
python3 src/run_case.py --case demo/case.json --out work
```

输出会列出问题条目与自动修正规则名，`text` 可直接拷回原稿。
